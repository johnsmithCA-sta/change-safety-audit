# 审计模板与量化脚本

## 量化脚本

```python
import os

def tok(s):
    """粗估 token：中文 0.9/字，英数 0.35/字符"""
    cjk = sum(1 for c in s if '\u4e00' <= c <= '\u9fff')
    return int(cjk * 0.9 + (len(s) - cjk) * 0.35)

def read(p):
    full = os.path.expanduser(p)
    return open(full, encoding='utf-8').read() if os.path.exists(full) else ""

# 按你的平台改这里。常见用户级身份/记忆文件：
#   WorkBuddy  ~/.workbuddy/{SOUL,IDENTITY,USER,MEMORY}.md
#   Claude     ~/.claude/CLAUDE.md
#   OpenClaw   各自工作空间的 memory 目录
TARGETS = [
    ("SOUL.md",    "~/.workbuddy/SOUL.md"),
    ("IDENTITY.md","~/.workbuddy/IDENTITY.md"),
    ("USER.md",    "~/.workbuddy/USER.md"),
    ("MEMORY.md",  "~/.workbuddy/MEMORY.md"),
]

total = 0
print(f"{'文件':<16}{'字节':>8}{'tokens':>9}")
print("-" * 34)
for name, path in TARGETS:
    s = read(path)
    t = tok(s)
    total += t
    print(f"{name:<16}{len(s.encode()):>8}{t:>9}")
print("-" * 34)
print(f"{'合计':<16}{'':>8}{total:>9}")
```

云端自动生成的 profile 通常另占 5,000+ tokens 且**本地不可控**，单独列出，避免把不可控项算进优化成果。

## 检查清单

### 明文凭据
```bash
grep -nE "sk_[a-zA-Z0-9_-]{10,}|[a-f0-9]{32}|SCT[0-9A-Za-z]{20,}|Bearer [A-Za-z0-9._-]{20,}" 目标文件
```
命中即改为指针：`落盘平台凭据目录（chmod 600），运行时 TOKEN=$(cat <凭据目录>/xxx) 注入`。各平台路径不同（WorkBuddy 为 `~/.workbuddy/keys/`，其他平台用等效 secrets 目录），按你的环境替换。

### 备份冗余（按 md5 去重）
```bash
cd 备份目录 && md5 *.md | awk '{print $4}' | sort | uniq -d
```
列出内容完全相同的文件名。保留一份，其余删除（删前 tar 归档）。

### 文件间重复
逐对检查，重点怀疑：
- USER.md 的「工作习惯」是否复述 SOUL.md 的「输出规范」
- 「反模式」是否是「核心原则」的否定式复述
- 身份文件与主文件是否都写了人格描述

### 非记忆文件混入记忆目录
记忆目录里应只有 `YYYY-MM-DD.md` 日志与 `MEMORY.md`。工具数据（清理基线、临时素材、`.DS_Store`）一律移出或删除。

## 产出模板

```
## 现状
| 文件 | tokens | 占比 | 问题 |
（云端不可控项单列，并另算本地可控层）

## 诊断
每条：病灶 → 证据 → 影响
证据必须可验证：md5、mtime、grep 命中数、审计日志条数、文件数

## 建议（分优先级）
P0 纯删减零风险
P1 结构去重
P2 安全优先（凭据明文）
P3 不可控项（只说明，不承诺收益）

## 验收标准
每项一条客观可判定条件
  填回内容 → 等 ≥ 观测窗口后 md5 与写入时一致
  备份策略 → 连续两次改动后备份目录文件数不增长
  目录清理 → 目录内只剩 X 类型文件
```

## 报告原则

1. **量化先行** —— 没有数字的优化是猜测
2. **证据可验证** —— 每条诊断附 md5 / mtime / grep 命中数，不附"我觉得"
3. **区分可控与不可控** —— 云端 profile 等只读项单独列出，不混进优化成果宣称
4. **周期未知时不下否定结论** —— 说「X 分钟内未观测到」，不说「不会」

## 治本四手法（优先于反复蒸馏）

| 手法 | 做法 | 为什么 |
|---|---|---|
| **索引化降级** | 把记忆文件从「全文仓库」降为「目录页」：每条压成一句规则 + 指针，正文外置到 skill / 工作区文档 / 凭据目录 | 蒸馏是**同层压缩**（有损、费 token、必反弹）；索引化是**跨层分流**（无损、一次到位） |
| **配额门禁** | 给每个受注入文件设硬配额（取其注入上限的 60–80% 作软线），写入前跑检查脚本，超线拒绝追加 | 把「事后超限」变成「事前拦截」；配额是纪律，不是建议 |
| **归档出注入目录** | 历史快照放独立的 `*-archive/` 目录，**不与受注入文件同目录** | 备份若落在注入目录内，等于把注入预算乘以备份份数 |
| **置换精炼（已超硬配额时）** | 已在配额之上就先删后加：**压措辞，不删事实** —— 保留全部「事实令牌」，压掉连接词与重复限定语 | 精简最常见的失败是**顺手删掉唯一记录**（如无远端仓库的 commit hash、服务器补丁路径） |

**两个隐藏膨胀源**：

- **并行会话**：多个会话同时写同一个记忆文件时各自追加、无人收敛，且会静默覆盖彼此改动。收到「文件已被修改」告警时**不要直接覆盖**——先读回现状、合并、再写。
- **先查再写**：动手前先确认目标位是否已有承接（grep 技能目录 / 工作区文档），避免「搬过去变成新副本」。

## 置换精炼的可证伪验收

重写信息密集文件时**别靠肉眼确认「没删东西」**——先把事实令牌逐个抄出来（不凭记忆），再用脚本断言：

```python
tokens = ["<文件路径>", "<commit hash>", "<service_id>", "<命令参数>", "<阈值>", "<日期>", ...]
t = open(F, encoding="utf-8").read()
print("缺失:", [k for k in tokens if k not in t] or "无")          # 事实层：一个都不能少
print("骨架:", [s for s in ["## 一", "## 二", "## 三"] if s not in t] or "齐全")  # 防整段被吞
```

- **该保全的令牌**：路径 / commit hash / service_id / 命令参数（如 `rsync -R`）/ 数值阈值 / 日期 —— 删掉就无法从上下文反推。
- **可安全删的**：已在链接文档里重复的分析细节、连接词、重复限定语、指向同一组文件的冗长枚举（三份报告改写成一条 glob + 括号说明）。
- **收尾**：跑配额门禁，确认从 `[OVER]` 回到 `[WARN]` / `[OK]`。
- 若纪律前提是「**清理不留备份**」，则**令牌保全断言就是备份的替代品**：不落任何副本，把可逆性交给机器可验证的断言。

## 决策根：规则 vs 快照

| 类型 | 特征 | 处置 |
|---|---|---|
| **规则** | 该怎么做事（偏好、硬约束、路由策略） | 短，值得每会话注入 |
| **快照** | 项目进展到哪了（版本号、批次、成本明细） | 长，按需检索，不进固定注入 |

膨胀几乎全部来自把快照当规则塞进记忆。自动生成的云端 profile 尤其容易塞满已完结项目的状态快照，且本地只读删不掉 —— 只能靠控制输入间接治理。

## 平台适配：注入目录与凭据目录因平台而异

**不要硬编码平台路径**：先探测存在性，再按本机实际路径执行。

| 平台 | 用户级身份 / 记忆文件 | 凭据目录 |
|---|---|---|
| WorkBuddy | `~/.workbuddy/{SOUL,IDENTITY,USER,MEMORY}.md` | `~/.workbuddy/keys/` |
| Claude Code | `~/.claude/CLAUDE.md`（另可能有项目级 `.claude/`） | 无固定约定 ⇒ 用环境变量或系统密钥管理器 |
| 其他工作空间型 Agent | 以该工作空间下的 memory 目录为准 | 按该平台配置 |
| 自建 / 未列平台 | 以本机**实际被加载**的文件为准（查客户端配置或注入清单） | 一律环境变量注入 |

**判定口径**：上表只是「常见位置」，**真正的判据是「本机是否真的注入它」**——探测不到就别硬套。脚本应把未命中的路径单独列为「路径不匹配或不适用本平台」，而不是当作错误。
