# Changelog — change-safety-audit

版本号语义化（主.次.修订）。条目按「**新增 / 优化 / 修复 / 调整**」四类，只写使用者可感知的变化。

## [1.3.1] - 2026-09-19

### 新增

- 「**删除前先枚举引用面**」一条：全类型检索（不得只搜 `*.md`）、覆盖四类非文档引用面、逐条区分「活引用」与「历史叙述」、判据写成可证伪断言。
- 铁律由三条扩为四条；同节给出「删除批次的正确形态」（判据清单 → 按编号获批 → 分批执行复核 → 全类型复查残留 → 修连带指针）。
- 「**批量改引用前先圈定 root**」：改一批文档里的路径引用时，root 只圈活跃文档，显式排除注入层（追加型日志只追加不许覆写）、代码仓、历史归档目录。
- 「**文档归集 / 搬家四步流程**」（`references/文档归集.md`）：md5 清单当反向依据（不留备份副本）→ 分批移动 + 两侧校验 → 移完 grep 旧路径找指针 → 历史用一条注记覆盖。
- 「**改上游产物前先枚举下游消费者**」：穷举消费者、列出四类二次加工风险、反向设计上游文案、验收走端到端 dry 跑。
- **平台适配**：注入目录与凭据目录按平台探测，不硬编码路径；量化脚本改为跨平台自动探测。

### 优化

- 触发词新增：删除前检索 / 引用面 / 唯一副本 / 无人依赖 / 清理旧文件 / 归档整理 / 批量删除 / 文档归集 / 搬家 / 批量改引用 / 圈定 root / 下游消费者 / 二次加工 / 端到端 dry 跑。
- 上下文瘦身新增「治本四手法」（索引化降级 / 配额门禁 / 归档出注入目录 / 置换精炼）与置换精炼的可证伪验收方法。

## [1.3.0] - 2026-09-15

### 新增

- 「**改上游产物前先枚举下游消费者**」一条：区分「解析正文」与「只取文件名 / mtime」的消费者、四类二次加工风险、反向设计上游文案、端到端 dry 跑验收。
- 次级规则「改事实型论断前用全量历史数据反证」，用于避免把样本偏差写成定理。

### 优化

- 触发词新增：下游消费者 / 二次加工 / 推送文案 / 被删括号 / 染色 / 端到端 dry 跑 / 定义类结论反证。

## [1.2.1] - 2026-09-13

### 调整
