# 文档归集 / 搬家

把散落文档按主题归集到一个目录时，按下面的顺序走 —— **别先搬再想**。

## 第 0 步（前置）：批量改引用前先**圈定 root**

归集完成后往往要批量把旧路径引用改成新路径。这一步的风险**不在替换本身，而在范围**：

**root 圈定规则**

| 处置 | 对象 |
|---|---|
| ✅ **圈进来** | **活跃文档**：项目速查表 / 记忆索引 / skill `references/` / playbook / 归集目录本身 |
| ⛔ **显式排除** | **注入层**（含**追加型日志，只追加不许覆写**）、**代码仓**、**历史归档目录** |

**三条判据**

1. **追加型日志永不批量改写** —— 日志的价值在「当时的真实记录」，改写等于伪造历史。
2. **生产源文件里的注释指针属「脚本改动」** ⇒ 必须**先请示、改后回同步上游**，不能顺手改（本机副本领先上游 = 下次同步会被覆盖回去）。
3. **root 用「目标清单」定义，不用「父目录」定义** —— 范围宁可事后补，不可事前超。

## 归集四步

### 1. 先出 md5 清单当「反向依据」，不留备份副本

清单记「**原位置 → 新位置 + 字节 + md5**」，写入目标目录（如 `MOVE-MANIFEST-YYYYMMDD.md`）。

移动可精确反向 ⇒ 满足「**清理不留备份**」口径，同时不牺牲可逆性：**md5 清单就是备份的替代品**。

### 2. 分批移动（≤10 个/批）+ 每批校验

移动后立刻核对**两侧**：「**源目录已无**」+「**目标目录已有**」。只看一侧会漏掉「没搬成功、源也没删」这种状态。

### 3. ⚠️ 移完必须 grep 旧路径找指针（最易漏）

指针**不只在本项目里**。至少覆盖四类引用面：

| 引用面 | 典型位置 |
|---|---|
| 跨项目文档 | 其他项目的工作区文档、项目速查表 |
| 技能包内 | 各技能 `references/` 与 SKILL.md |
| 代码与脚本 | 服务器脚本的**输出字符串**、脚本注释 |
| 台账与索引 | 技能台账、清单类文档 |

> 顺带收益：**引用面检索同时也是指针体检** —— 能查出本来就已悬空的旧指针。

### 4. 历史记录别改写，用一条注记覆盖

changelog / 台账之类的历史文档里满是旧文档名，**逐条改 = 改写历史**。

改为在该文件的维护节**加一条「文档归集」注记**，声明「文中出现的『工作区《…》』一律按新目录解析」⇒ **一处生效、历史保真**。

## 归集产物若要外发：先做「环境脱敏」

归集常常是为了「攒成一份可外发的东西」（发给同事 / 打进技能包 / 上平台）。**进入外发流程前，先对本机专属标识做一遍替换**：

| 必须替换 | 替换为 |
|---|---|
| 本机工作区目录名、项目名、私有仓库 / 脚本文件名 | 「某工作区 / 生产仓库 / 抓取脚本」这类**角色名** |
| 服务器内部路径、服务名 | 「服务器上的……脚本」 |
| 特定平台凭据的**文件名 / 键名**（只写名字也算泄露） | 「代码托管 PAT / webhook / 签名私钥」这类**类别名** |

**判定口径**：**对任何使用者都成立的通用约定可以留**（如 Agent 平台的记忆目录、公开的第三方接口**类别**）；**只有你本机才成立的东西必须换**。

⚠️ **工具门禁通常会放行这类词**（路径类检查多可豁免）⇒ **「门禁 PASS」不能替代人工过一遍**。写规则、写示例时最容易顺手带上本机路径 —— 那正是泄露源。

## 工具坑

`grep "a\|b"` 在 macOS **BSD grep 下不支持 `\|` 交替**，会给出**空结果的假阴性**：

- 曾据此判定「**无残留指针**」而收工
- 另一次调研也因同一原因把「早就有」误判成「缺失」，并把它排成最高优先级

⇒ **多分支匹配一律用 Grep 工具或 `grep -E "a|b"`。bash grep 的空结果，永远不能作为「不存在」的证据。**
