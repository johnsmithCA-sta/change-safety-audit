# 变更安全与上下文卫生

一个聚焦用途：**让"删/改文件"和"清理上下文"这两件事不出事、不返工。**

## 触发词

- 删除文件 / 文件夹删 / 清空目录 / 批量重命名
- 配置改动验证 / 改回默认值 / md5 验收 / md5
- 备份策略 / 备份文件名 / 备份防熵增 / 要不要备份 / 默认不留备份
- 自动重建 / 被重建 / 删了又回来 / 受管文件
- 上下文瘦身 / 清理上下文 / 上下文 / 记忆文件 / 每会话注入
- 凭据明文 / 身份文件重复 / 多 agent 互评 / 多 agent 改动
- 多 agent 分工 / 多 agent 编排 / 并行整改 / 并行编辑 / 并行改一批文件

## 何时不用

- 单个新建文件（不涉及删除，无重建风险）
- 纯代码改动且有测试覆盖（测试就是验收）
- 临时文件、缓存目录（删了无所谓，不需要判定）

## 三条铁律（动手前先过）

1. **受管文件先判定** —— 有些文件删了会被平台重建。判定只能靠实验，且必须遵守观测窗口规则。
2. **验收比对 md5** —— 文件"还在"不等于"内容没被改回默认值"。
3. **默认不留备份** —— 先问「这次操作可逆吗」。可逆（改动可精确反向 / 上游 git / 系统废纸篓兜底）就不留任何副本；仅当退路全无才留底，且**固定名同名覆盖、不写日期**（备份名带日期 = 必然熵增）。

踩坑实例与完整推导见 `references/硬规则详解.md`。

## 审计五步（上下文瘦身）

1. **量化** —— 跑 `scripts/audit_tokens.py`，先出占比表再动刀
2. **查重** —— 文件间互相复述的，留一处作单一事实源，其余改成指针
3. **扫凭据** —— 凭据永不进记忆，只留平台凭据目录指针（各平台路径不同，一律 chmod 600）
4. **定受管** —— 按铁律 1 做实验
5. **写验收** —— 每项一条客观可判定条件：md5 一致 / 文件数不增长 / 目录只剩 X

量化脚本、检查清单与产出模板见 `references/审计模板.md`。

### 五步之外：三个结构性手法（治本，优先于反复蒸馏）

| 手法 | 做法 | 为什么 |
|---|---|---|
| **索引化降级** | 把记忆文件从「全文仓库」降为「目录页」：每条压成一句规则 + 指针，正文外置到 skill / 工作区文档 / 凭据目录 | 蒸馏是**同层压缩**（有损、费 token、必反弹）；索引化是**跨层分流**（无损、一次到位） |
| **配额门禁** | 给每个受注入文件设硬配额（取其注入上限的 60–80% 作软线），写入前跑检查脚本，超线拒绝追加 | 把「事后超限」变成「事前拦截」；配额是纪律，不是建议 |
| **归档出注入目录** | 历史快照放独立的 `*-archive/` 目录，**不与受注入文件同目录** | 备份若落在注入目录内，等于把注入预算乘以备份份数 |

**并行会话是隐藏的膨胀源**：多个会话同时写同一个记忆文件时各自追加、无人收敛，且会静默覆盖彼此改动。收到「文件已被修改」告警时**不要直接覆盖**——先读回现状、合并、再写。

**先查再写**：动手前先确认目标位是否已有承接（grep 技能目录 / 工作区文档），避免「搬过去变成新副本」。

## 决策根：规则 vs 快照

| 类型 | 特征 | 处置 |
|---|---|---|
| **规则** | 该怎么做事（偏好、硬约束、路由策略） | 短，值得每会话注入 |
| **快照** | 项目进展到哪了（版本号、批次、成本明细） | 长，按需检索，不进固定注入 |

膨胀几乎全部来自把快照当规则塞进记忆。自动生成的 profile 尤其容易塞满已完结项目的状态快照，且本地只读删不掉——只能靠控制输入间接治理。

## 多 agent 并行改动的编排（执行方）

要把一批改动分派给多个 agent / 多个会话并行做时，先过四条分工纪律：

1. **按「文件」切分，不按「条目」切分** —— 一个文件只能有一个写入者；条目常横跨多文件，须按文件边界重新归并。风险最高、要能反向验证的那部分留给自己做。
2. **跨文件共享口径逐字下发** —— 同一个常量出现在两处以上就会漂，把口径原样粘进每份指令并声明「另几组也在同步」。
3. **同文件的「读—改—写」一律串行** —— 并发下发两个 Edit 会互相覆盖（两边都报成功）；**脚本批量改多处时，替换必须累积到同一份文本**，且「断言命中次数」挡不住覆盖（实测 7 处只落 1 处）⇒ 每条改动后**回读新串**确认，不凭工具自报成功判定。
4. **要求对方报「没做到的」** —— 并点名硬约束（不重排既有编号、不写来源与日期、不动可写范围外的文件）。

收尾的 **10 步终检序列只能由主 agent 做**（语法 → 门禁默认+严格 → 新逻辑正/反/边界 → 基线逐项回归 → 锚点 → 断链 → 残留词 → 红线 → 残留清理 → 逐文件核对基线 diff）。

判据、清单与实测踩坑见 `references/并行编排与终检.md`。

## 多 agent 互评要不要

命中 ≥2 条就值：不可逆 / 存在黑盒行为 / 执行者有利害关系 / 主观取舍 / 事实可证伪。

**关键操作**：给第二方的指令要写「找出我错了的地方，每条附可验证证据」，**不要**写「请评估这个方案」——前者逼出证伪，后者滑向附和。

判据与价值衰减曲线见 `references/互评判据.md`。
