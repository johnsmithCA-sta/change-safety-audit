# 变更安全与上下文卫生

一个聚焦用途：**让"删/改文件"和"清理上下文"这两件事不出事、不返工。**

## 触发词

- 删除文件 / 文件夹删 / 清空目录 / 批量重命名
- 配置改动验证 / 改回默认值 / md5 验收 / md5
- 备份策略 / 备份文件名 / 备份防熵增
- 自动重建 / 被重建 / 删了又回来 / 受管文件
- 上下文瘦身 / 清理上下文 / 上下文 / 记忆文件 / 每会话注入
- 凭据明文 / 身份文件重复 / 多 agent 互评 / 多 agent 改动

## 何时不用

- 新建文件（不涉及删除，无重建风险）
- 纯代码改动且有测试覆盖（测试就是验收）
- 临时文件、缓存目录（删了无所谓，不需要判定）

## 三条铁律（动手前先过）

1. **受管文件先判定** —— 有些文件删了会被平台重建。判定只能靠实验，且必须遵守观测窗口规则。
2. **验收比对 md5** —— 文件"还在"不等于"内容没被改回默认值"。
3. **备份用固定名同名覆盖** —— 备份名里带日期 = 必然熵增。

踩坑实例与完整推导见 `references/硬规则详解.md`。

## 审计五步（上下文瘦身）

1. **量化** —— 跑 `scripts/audit_tokens.py`，先出占比表再动刀
2. **查重** —— 文件间互相复述的，留一处作单一事实源，其余改成指针
3. **扫凭据** —— 凭据永不进记忆，只留平台凭据目录指针（各平台路径不同，一律 chmod 600）
4. **定受管** —— 按铁律 1 做实验
5. **写验收** —— 每项一条客观可判定条件：md5 一致 / 文件数不增长 / 目录只剩 X

量化脚本、检查清单与产出模板见 `references/审计模板.md`。

## 决策根：规则 vs 快照

| 类型 | 特征 | 处置 |
|---|---|---|
| **规则** | 该怎么做事（偏好、硬约束、路由策略） | 短，值得每会话注入 |
| **快照** | 项目进展到哪了（版本号、批次、成本明细） | 长，按需检索，不进固定注入 |

膨胀几乎全部来自把快照当规则塞进记忆。自动生成的 profile 尤其容易塞满已完结项目的状态快照，且本地只读删不掉——只能靠控制输入间接治理。

## 多 agent 互评要不要

命中 ≥2 条就值：不可逆 / 存在黑盒行为 / 执行者有利害关系 / 主观取舍 / 事实可证伪。

**关键操作**：给第二方的指令要写「找出我错了的地方，每条附可验证证据」，**不要**写「请评估这个方案」——前者逼出证伪，后者滑向附和。

判据与价值衰减曲线见 `references/互评判据.md`。
