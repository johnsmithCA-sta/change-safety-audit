# 变更安全审计

把「删文件 / 改文件 / 搬文件 / 清上下文」四类高风险动作，从「凭感觉动手」变成**先核验、后可逆、可证伪**的流程。

## 定位

一套动手前的核验规则集：判断哪些文件删不得（受管文件）、删之前谁在引用它（引用面 / 唯一副本）、怎么证明改对了（md5 / 端到端 dry 跑）、什么时候不该留备份、上下文注入怎么瘦身、多 agent 并行改动怎么分工收尾。**只出规则与判据，不代执行删除。**

## 何时用（适用 / 不适用）

- **用它**：准备删除 / 清空 / 批量重命名 / 归档整理；改完配置需要验证；担心文件被平台自动重建；怀疑每会话注入的上下文过于臃肿；要把一批改动分给多个 agent 并行做；要改会被下游二次加工的中间产物（推送文案 / 报表 / 导出文件）；要把一批散落文档按主题归集搬家。
- **不用它**：单个新建文件（无重建风险）；有测试覆盖的纯代码改动（测试就是验收）；临时文件与缓存目录（删了无所谓）；常规代码审查与性能评估。

## 触发词

- 删除文件 / 文件夹删 / 清空目录 / 批量重命名

- 自动重建 / 被重建 / 删了又回来 / 受管文件
- 上下文瘦身 / 清理上下文 / 上下文 / 记忆文件 / 每会话注入
- 凭据明文 / 身份文件重复 / 多 agent 互评 / 多 agent 改动
- 多 agent 分工 / 多 agent 编排 / 并行整改 / 并行编辑 / 并行改一批文件
- 下游消费者 / 二次加工 / 推送文案 / 被删括号 / 染色 / 端到端 dry 跑 / 定义类结论反证

## Goal（可验证输出物）

一次核验跑完，应交付四样东西：

1. **判据清单** —— 每个待处理对象一行：对象 / 体积 / 依据（可证伪的检索结果或实验记录）；
2. **获批范围** —— 按编号获批的批次，不擅自扩大；
3. **每批复核记录** —— 执行后的 `ls` / md5 等客观结果；
4. **残留引用复查** —— 全类型检索结果（0 命中，或命中项已逐条分桶为「活引用 / 历史叙述 / 别名 / 已完成待办物料」）。

## Inputs（必填 / 可选）

- **必填**：待处理的对象（文件 / 目录 / 清单）+ 动作类型（删 / 改 / 搬 / 瘦身）。
- **可选**：可接受的不可逆程度；该批是否已获批；注入目录与凭据目录的实际位置（**各平台不同，以探测结果为准**，对照表见 `references/审计模板.md`）。

## Constraints（不做什么 + 质量门槛 + 逃逸条款）

- **不处理**：单个新建文件、有测试覆盖的纯代码改动、临时文件与缓存。
- **质量门槛**：每条结论必须**可证伪** —— 把「无人依赖」「没被改回默认值」写成可断言的检查（0 命中 / md5 一致 / 两侧校验），不靠主观印象。**拿不准的一律列为候选上报，不并入批量执行。**
- **不硬编码平台路径**：用相对路径、环境变量或探测结果，不用本机绝对路径 —— 绝对路径换台机器就断，还会暴露本机目录形态。
- **逃逸条款**：当本文件的规则与用户明确意图冲突或不适用时，**优先保障用户数据与意图**，并显式说明偏离理由与替代动作，不得静默偏离。

## Steps（读取 → 处理 → 验证）

1. **读取** —— 先用「决策路径」定动作类型，再取对应规则组与其详解。
2. **处理** —— 按规则组核验（见「规则速查」）；需要动手的，**先出判据清单 → 经确认 → 再分批执行**（≤10 个/批）。
3. **验证** —— 验收三件套：① **数量统计**（删除数 / 文件数不增长）② **逐条抽查**（回读关键内容，不凭工具自报成功）③ **失败清单**（未达成项如实登记，不装饰）。

## 决策路径

- 动作是**删除 / 清空 / 归档** → 走「受管文件 + 引用面 + 唯一副本」规则组。
- 动作是**改会被下游二次加工的产物** → 先枚举全部消费者，再反向设计上游文案。
- 动作是**批量改引用 / 搬文档 / 归集** → 先**圈定 root**，再按归集四步走（`references/文档归集.md`）。
- 动作是**清上下文 / 瘦身记忆** → 走「审计五步 + 治本四手法」（`references/审计模板.md`）。
- 动作是**分派给多个 agent** → 先过四条分工纪律；收尾的 10 步终检只由主 agent 做（`references/并行编排与终检.md`）。

## 规则速查

| 规则 | 判据 | 详解 |
|---|---|---|
| **受管文件先判定** | 删了会被平台重建的文件，只能靠「删除 → 等满观测窗口 → 复核」实验判定；周期未知时只能说「X 分钟内未观测到」，不下否定结论 | `references/硬规则详解.md` 铁律一 |
| **验收比对 md5** | 「文件还在」≠「内容没被改回默认值」 | 铁律二 |
| **默认不留备份** | 先问可逆性：可逆就不留任何副本；要留则**固定名同名覆盖、不写日期** | 铁律三 |
| **删除前查引用面** | 全类型检索（**不得只搜 `*.md`**）+ 逐条分「活引用 / 历史叙述 / 别名」，否则删掉的可能不是冗余、而是**唯一副本** | 铁律四 |
| **改上游先枚举下游** | 解析正文的消费者一律先跑通验证；关键语义不得写进会被清洗的结构；验收走端到端 dry 跑 | 铁律五 |
| **批量改引用先圈定 root** | root 只圈活跃文档；**显式排除**注入层（追加型日志只追加不许覆写）、代码仓、历史归档目录 | `references/文档归集.md` |
| **归集四步** | md5 清单当反向依据（不留备份副本）→ 分批移动 + 两侧校验 → grep 旧路径找指针 → 历史用一条注记覆盖 | 同上 |
| **审计五步** | 量化（跑 `scripts/audit_tokens.py`，跨平台自动探测注入文件）→ 查重 → 扫凭据 → 定受管 → 写验收 | `references/审计模板.md` |
| **多 agent 分工** | 按文件切分（一文件一写入者）、共享口径逐字下发、同文件读写串行、要求对方报「没做到的」 | `references/并行编排与终检.md` |
| **多 agent 互评** | 命中 ≥2 条就值：不可逆 / 存在黑盒行为 / 执行者有利害关系 / 主观取舍 / 事实可证伪 | `references/互评判据.md` |

## Verification Checklist

- [ ] 每条结论都有可证伪依据（检索命中数 / md5 / 实验记录），没有「应该没人用」这类主观判断
- [ ] 删除类动作已穷举**全类型**引用面，命中项已逐条分桶
- [ ] 备份决策已按可逆性判定；需要留底时文件名固定、不含日期
- [ ] 改动类动作已跑完端到端 dry 跑，看的是最终渲染结果而非上游 stdout
- [ ] 批量改引用已圈定 root，且排除了注入层 / 代码仓 / 历史归档
- [ ] 每批执行后已回读复核，未达成项已列入失败清单

## 使用示例

> 用户：「工作区里这些旧文档我想清掉一批，顺便把散落的说明文档归到一个目录。」

1. 定动作类型 → 同时含「删除」与「归集」两类，分别走各自规则组（见「决策路径」）。
2. 删除组：对每个候选做**全类型**引用面检索（不限扩展名），逐条分「活引用 / 历史叙述 / 别名」；判定是否受管文件。
3. 出**判据清单**（对象 / 体积 / 依据）→ 交用户按编号批准。
4. 归集组：**先圈定 root**（只圈活跃文档），出 md5 清单；分批移动（≤10 个/批），每批校验「源目录已无 + 目标目录已有」。
5. 移完 `grep` 旧路径找指针（跨项目、含技能 `references/` 与脚本输出串）。
6. 分批删除 + 每批复核；最后全类型复查残留引用。
7. 输出：判据清单 + 复核记录 + 残留复查结果 + 未达成项清单。

## 常见错误

| 现象 | 修复 |
|---|---|
| 「这个没人要了吧」就删 | 改成可证伪断言：全类型检索 N 命中，逐条分桶后 0 个活引用 |
| 只搜 `*.md` 就判定无引用 | 引用常在 `.py` 的 docstring / 配置 JSON / 自动化 prompt 里，必须不限扩展名 |
| 删目录用递归强制删除 | 先逐个删掉列明的文件，再用「只删空目录」的方式收尾 —— 非空会报错，而不是静默带走清单外的东西 |
| 只看上游 stdout 就认为改对了 | 跑完整【上游生产 → 下游消费】链，打印最终渲染结果 |
| 把「清理不留备份」用在不可逆操作上 | 先问可逆性：不可逆（覆盖远端历史、受管文件）才留底，且只留一处 |
| 用本机绝对路径写规则或脚本 | 用相对路径、环境变量或探测结果；各平台注入目录与凭据目录不同 |
