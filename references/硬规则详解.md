# 硬规则详解（含踩坑实例）

## 铁律一：受管文件先判定

### 什么是受管文件
删除后会被平台/宿主进程自动重建的文件。典型特征：由引导流程或初始化逻辑持有模板，内容可在历史会话轨迹中检索到，但**磁盘上没有独立的模板源文件**。

### 判定方法：实验 + 观测窗口规则

```
1. 备份当前内容到 /tmp
2. 删除文件，记录精确时刻
3. 等待 ≥ 观测窗口后 ls 复核
4. 若重建 → 受管文件，改「填回内容」而非硬删
```

### 观测窗口规则（血泪）

> 对「某机制不存在」的判定，观测窗口必须 **≥ 该机制已知最大周期**。周期未知时，只能说「X 分钟内未观测到」，**不得下否定结论**。

**踩坑实例**：删除受管文件后观察 4.5 分钟未见重建 → 下结论「删即最终解」→ 第 11 分钟文件重生，结论作废，整轮返工。

配套证据链（用于排除"自己写回"的可能）：
- 审计日志里检索该文件名，命中数
- 全盘搜模板原文，确认是否有独立模板源文件
- 核对文件 mtime 与自己的操作时刻

### 受管文件的正确处置：顺势填回，不要对抗

确认删不掉后，填入正确内容。但填回时**只写该文件独有的结构化字段**，其余用一行指针指回单一事实源，**绝不复制**主文件里的散文描述——否则制造新的双事实源，等于白做。

目标：填回后的文件应比默认模板还小。实例中 582 B 空模板 → 449 B 有效内容。

## 铁律二：验收比对 md5

文件「还在」不等于「内容没被改回默认值」。若重建逻辑是「发现为空模板/为默认则重置」，填回也会被覆盖，而"文件存在"这个检查完全验不出来。

```bash
md5 -q 文件 > /tmp/baseline_md5.txt        # 改动后立刻存档
# 等满观测窗口
[ "$(cat /tmp/baseline_md5.txt)" = "$(md5 -q 文件)" ] && echo "通过" || echo "被重置"
```

成本零，堵住推论的最后漏洞。

## 铁律三：备份用固定名同名覆盖

```
补丁/次版本 → 固定名 XXX.backup.md（同名覆盖，不写日期）
主版本     → 带版本号另存 XXX.vX.Y.Z.md（保留回退能力）
```

**最容易漏的一点：文件名必须固定。** 若沿用「版本号+日期」命名，每次都是新文件名，「同名覆盖」根本不可能发生——规则写了等于没写。

实例：某章程写了「同名覆盖不留多份」，但未定义文件名，实际每次备份仍是 `SOUL.v1.0.0.20260827.md` 这类带日期的新文件，一轮操作产生 5 个备份、50% 内容重复。

删减前先 `tar` 打包归档，保证可回退。

**还要检查自动化**：已存在的定时任务里若写死了旧的「带日期」备份规则，会持续架空新章程。改章程后必须同步检查自动化 prompt。

## 附：三条次级规则

### 下沉前先 grep
打算把某段技术细节「下沉到 skill」之前，**先 grep 目标 skill**。很可能它已经写得比你手上的副本更完整——那就直接删副本，不用下沉。实例中这一步省掉了约一半工作量。

### 技术细节的归属
```
技术细节 → 对应 skill
项目状态 → 项目 memory
跨项目跨时间的稳定偏好 → 用户级 MEMORY.md
凭据 → 平台凭据目录（chmod 600，只留指针，如 WorkBuddy 的 `~/.workbuddy/keys/`）
运维配置 → 代码与复盘文档
```

### 时效项必须配触发机制
只标「到期日」而不设扫描触发，等于没标。要么写进自动化（每月扫一次带到期日的条目），要么写进定期审视任务。
