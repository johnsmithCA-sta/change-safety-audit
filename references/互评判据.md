# 多 agent 互评判据

## 何时值得

命中 **≥2 条** 就该拉第二意见：

| 判据 | 说明 |
|---|---|
| **不可逆 / 难回退** | 删文件、改配置、发布。错了代价高 |
| **存在黑盒行为** | 平台或第三方机制未知，单个 agent 容易困在自己的假设里 |
| **执行者有利害关系** | 刚做过的人会自我辩护，需要外部视角戳穿 |
| **主观取舍** | 留什么删什么没有标准答案，需要第二意见校准 |
| **事实可证伪** | 有客观证据可查，互评才有意义；纯观点交换不值得 |

## 何时不值得

纯创作、可逆的低风险改动、有标准答案的任务、时间敏感的任务。互评是成本，不是仪式。

## 关键操作：指令措辞决定成败

| 写法 | 结果 |
|---|---|
| 「请评估这个方案」 | 滑向确认与附和，产出「✅ 属实」式无效核对 |
| 「**找出我错了的地方，每条附可验证证据**」 | 逼出证伪，产出真正有价值的反驳 |

互评的价值不在于"更聪明"，而在于**打破单个 agent 的确认偏误**。如果第二方只是复述和确认，这轮互评是净浪费。

## 价值分布：第二轮之后急剧衰减

实例（一次三轮互评的实测）：

| 轮次 | 动作 | 价值 |
|---|---|---|
| 1 | 用「文件在 11 分钟后重生」推翻「删即最终解」 | **高** |
| 1 | 用 mtime 证据推翻「这是上一轮残留」的自我辩护 | **高** |
| 2 | 补充「验收须比对 md5」「同名覆盖需主版本例外」 | 中 |
| 3 | 全盘接受 + 两条小补充 | **低** |

**结论：互评的红利主要在第二轮吃完，第三轮边际收益趋近于零。** 不要为了对称而凑第三轮。

## 固化的三条路径

经验不要只留在记忆里，三层都要落：

| 层 | 作用 | 适用内容 |
|---|---|---|
| **Skill** | 可执行流程 | 照着做的规则、checklist、workflow |
| **自动化** | 定期触发 | 「标了到期日但没人看」的条目、周期性体检 |
| **CHANGELOG / memory** | 教训归档 | **自己犯的错**，写明错因而非只写结论 |

判断归属的原则：**可执行工作流 → Skill；信息性事实 → memory。**

## 反模式

- **凑轮次** —— 第三轮全盘接受还硬凑，浪费双方上下文
- **核对表充数** —— 五条「✅ 属实」不如一条「你这个结论错了，证据是 X」
- **归因甩锅** —— 把可逆的误操作说成「平台黑盒行为」，会把"立刻能修"升级成"先摸清机制"，成本翻倍。先做实验证伪，再谈归因
- **结论跑在证据前面** —— 说了「要先验证平台行为」，下一句又推荐具体方案
